1 핵심 결론 (Executive Summary)

ARTEX는 전통 스캐너(sqlmap·nikto)도, 수동 공격자도 아닌 LLM이 응답을 읽고 다음 수를 결정하는 자율 에이전트다. 따라서 "페이로드 시그니처" 중심의 탐지로는 놓치기 쉽고, 아키텍처가 강제하는 구조적 지문을 노려야 한다. 관제가 잡아야 할 ARTEX의 3대 특징:

1

단일 기록 프록시(MITM) 집중 egress

모든 타깃 트래픽(curl·WebFetch·헤드리스 브라우저·네이티브 HTTP·DNS·enrich)이 하나의 기록 프록시를 거쳐 단일 호스트 IP에서 egress. 서로 다른 공격 벡터가 한 출발지에서 동시 관측되는 것이 최대 단서.

2

혼재된 클라이언트 정체성

같은 IP가 artex-enrich/1.0·Go HTTP·curl·모바일(Pixel 10) 에뮬레이션 헤드리스 Chromium까지 상이한 UA·TLS 지문을 한 세션에서 번갈아 낸다.

3

LLM 리듬 — 버스트 후 쿨다운

추론 지연·레이트리밋·휴먼승인 대기로 짧은 폭주 → 수십 초~수 분 침묵 → 재개의 계단형 리듬. 스캐너의 연속 폭주와도, 사람의 불규칙과도 다른 기계적·간헐적 패턴.

3 네트워크·트래픽 지문 (무엇을 볼 것인가)

3.1 단일 출발지에 다종 벡터 집중 최우선 신호

  • ARTEX는 기록 프록시로 egress를 모으므로, 하나의 소스 IP에서 DNS 정찰 → 웹 프로브 → 로그인 → 주입/업로드 → 브라우저 렌더링이 짧은 시간에 순차·혼재되어 관측.
  • 탐지(의사 규칙): 동일 src_ip AND 세션창(예:10분) 내 서로 다른 공격 범주 ≥ 3종 → 자동 에이전트 의심 경보. 스캐너는 벡터가 단조로우나 ARTEX는 "지능형 다벡터".

3.2 클라이언트 정체성 모순

  • UA 리터럴: artex-enrich/1.0 는 enrich 고정 문자열 → WAF/로그 즉시 탐지 룰 가치 최상.
  • UA ↔ 네트워크 불일치: 모바일 UA인데 데이터센터/VPS 대역 = 강한 봇 신호.
  • TLS/JA3·JA4 혼재: Go crypto/tls·Chromium·curl 핸드셰이크 지문이 한 IP에서 교차 출현.
  • 탐지: src_ip 단위 distinct(UA) ≥ 2 AND distinct(JA3) ≥ 2 → 오케스트레이션 의심.

3.3 자산 정찰 패턴 (enrich)

  • 파비콘·타이틀·헤더 수집형 단발 GET이 자산마다 1회(중복 억제), 응답 1 MiB에서 절단.
  • 탐지: artex-enrich/1.0 또는 "자산별 1회 루트/파비콘 프로브 후 중복 없음" 패턴.

4 행위·시간 지문 (어떻게 움직이는가)

4.1 LLM 리듬 — 버스트/쿨다운 계단형

  • tool-call마다 모델 추론 지연(수 초) 삽입 → 연속 폭주가 아닌 작은 버스트 + 규칙적 갭.
  • 429/5xx 시 백오프(1분 → 5분 → 30분) → 수 분 침묵 후 정확히 재개. 무료 티어 분당 20요청 초과 시 엔진 정지 후 창 리셋 재가동(본 세션 실측).
  • 탐지(시간분포): 요청 간격 저엔트로피 + 수 분 주기 침묵/재개 반복 = 자동 에이전트. 사람은 불규칙, 스캐너는 고밀도 연속 — ARTEX는 중밀도·간헐·정시 재개로 구별.

4.2 적응형 다단계 체인 (의미 의존 요청열)

  • LLM이 직전 응답을 읽고 다음 요청을 구성: 정보 노출 → 그 값을 쓴 후속 요청, 인증 정보 획득 → 곧바로 정상 자격증명으로 로그인(스캐너 불가 자율 체인).
  • 탐지(상관): 대용량/민감 응답 → 동일 IP의 논리적 후속(인증 성공·권한 상승) within 초~분 상관룰.

4.3 저소음·고정밀

  • sqlmap류 수천 요청 무차별과 달리 소수의 잘 구성된 요청으로 목적 달성(토큰·요청 효율 지향).
  • 탐지: "요청 수는 적으나 성공률/민감 엔드포인트 적중률이 비정상적으로 높은" 세션.

4.4 휴먼-인-더-루프 승인 갭

  • guard/intercept의 ask 승인 대기 시 능동 요청이 블로킹(정지) → 또 다른 비인적 정지 구간.

핵심 — ARTEX는 "사람처럼 적응하되 기계처럼 규칙적으로 멈춘다". 이 적응성과 기계적 리듬의 공존이 다른 어떤 주체와도 다른 ARTEX만의 지문이며, 단일 지표보다 6장의 다지표 상관으로 판정한다.

6 탐지 규칙 및 SIEM 상관 전략

6.1 단일 지표 룰 (1차 알림)

  • UA == artex-enrich/1.0 (미래 변형 대비 artex-* 정규식)
  • 모바일 UA ↔ 데이터센터/VPS ASN 불일치
  • 동일 IP에서 distinct(UA) ≥ 2 AND distinct(JA3/JA4) ≥ 2 (세션창 내)

7 대응 플레이북 (AI 에이전트 공격)

7.1 능동 완화 — "리듬을 깨라"

  1. 레이트 리밋/속도 제한이 가장 실효적. ARTEX는 상위 LLM 분당 한도(429)만으로도 자동 엔진이 멈췄다 — 방어측 속도 제한은 자동화 공격을 구조적으로 지연·중단시킨다.
  2. 단일 egress IP 차단/챌린지 — 집중 egress 특성상 IP 레벨 대응의 비용 대비 효과가 크다.
  3. 봇 챌린지(PoW/JS/행위) — 헤드리스 Chromium은 통과하나, Go/curl 경로와 모바일UA 모순이 챌린지 단계에서 추가 노출된다.

7.2 침해 대응 (체인 완성 정황 시)

  • 적응형 체인(민감응답→인증성공) 확인 시 자격증명 유출 가정: 영향 계정 전수 재설정·세션 만료.
  • RCE/업로드 정황은 서버측(프로세스 계보·FIM·아웃바운드) 교차 확인 후 호스트 격리.
  • 증거 보존: 공격 IP·UA 집합·JA3 지문·요청 타임라인(버스트/갭)·업로드 산출물 해시.

7.3 역추적·귀속

  • UA/JA3 집합과 리듬 지문을 IOC화하여 재출현 탐지. artex-* UA·모바일↔DC 불일치는 동일 도구 재사용 식별에 유효.
  • ARTEX의 llmrec(LLM 전량 녹화)는 공격측 산출물이나, 침해가 운영 주체와 연계될 경우 tool-call 타임라인·프롬프트·토큰 기록이 TTP 재구성·귀속의 1차 증거가 된다.

8 LLM 녹화 자료의 관제적 활용

ARTEX의 녹화(세션 트레이스·llmrec)는 공격자 측 기록이지만, 관제가 동일 패턴 재탐지를 위해 행위 모델(TTP 템플릿)로 역이용할 수 있다.

  • TTP 템플릿화: 단계열(정찰→로그인폼/토큰 인지→모듈 순회→주입/업로드→사후활용)을 상관룰 시나리오 템플릿으로 전환(6.2 참조).
  • 리듬 베이스라인: tool-call 간격·백오프 구간을 "자동 에이전트 시간 서명"으로 학습시켜 타임시리즈 이상탐지 레이블로 활용.
  • 지문 사전 구축: enrich UA·Go/curl/모바일Chromium의 UA·JA3 조합을 ARTEX 지문 사전으로 유지·대조.

9 관제 운영 권고 요약

  1. 주체를 탐지하라 — 취약점이 아니라 ARTEX의 구조적 지문(단일 프록시 egress·혼재 UA/TLS·LLM 리듬)을 노린다.
  2. artex-enrich/1.0 즉시 룰화 — 고정 리터럴은 비용 0의 고가치 시그니처.
  3. "모바일 UA ↔ 데이터센터 IP" 불일치를 상시 플래그.
  4. 시간분포를 본다 — 저엔트로피 간격 + 수분 주기 침묵/재개 = 자동 에이전트 서명.
  5. 적응형 체인을 상관으로 잡는다 — 민감응답→논리적 후속(인증성공)은 Critical.
  6. 레이트 리밋으로 구조적 완화 — LLM 한도만으로도 멈추는 특성을 방어측이 선제 적용.
  7. 다지표 합산 판정 — 단일 UA/IP가 아니라 복수 지표 상관으로 오탐을 줄인다.

10 결론

10.1 패러다임 전환 — "무엇을 쐈는가"에서 "누가 쏘는가"로

ARTEX 분석이 관제에 주는 핵심 교훈은, 방어의 무게중심을 페이로드(취약점·공격 문자열)에서 공격 주체(자율 에이전트)의 구조적 지문으로 옮겨야 한다는 것이다. LLM이 응답을 읽고 다음 수를 스스로 결정하는 이상, 페이로드는 매번 새로 조립되고 시그니처는 쉽게 빗나간다. 반면 에이전트의 아키텍처가 강제하는 행위·트래픽 지문은 공격자가 도구를 재설계하지 않는 한 남는다. 즉, ARTEX 대응은 하나의 룰이 아니라 탐지 철학의 교체다.

10.2 지표의 내구성 위계 — 어디에 베팅할 것인가

모든 지표가 같은 가치를 갖지 않는다. 회피 비용(공격자가 바꾸기 얼마나 쉬운가) 기준으로 세 층위로 나누어 자원 배분 우선순위를 정한다.

결론적 베팅 — 취약 지표는 공짜 알림으로 깔아두되, 최종 판정은 견고 지표(특히 "민감 응답 → 논리적 후속"의 의미 상관)에 건다. 적응형 체인은 ARTEX가 LLM 에이전트인 한 구조적으로 남는, 가장 모방하기 어려운 서명이다.

10.4 한계와 잔존 리스크 (정직한 경계)

본 방안은 확정 차단이 아니라 탐지 확률의 제고다. 역량 있는 공격자는 다음으로 지문을 흐릴 수 있다.

  • egress 분산(다중 IP·주거용 프록시) → "단일 IP 집중" 신호 약화
  • UA/TLS 랜덤화 및 인적 지터 주입 → 혼재·저엔트로피 신호 희석
  • 헤드리스 브라우저 위장 강화 → 봇 챌린지 일부 우회
따라서 ① 단일 지표 과신 금지(다지표 상관으로만 판정), ② 심층 방어(레이트 리밋·인증 강화·자격증명 위생은 에이전트 종류와 무관하게 유효), ③ 견고 지표 우선이 원칙이다. 분산·랜덤화에도 LLM 추론 지연과 응답 의존적 적응 체인은 구조적으로 남으므로, 여기에 탐지 역량을 집중하는 것이 가장 비용 효율적이다.

10.5 전망 — 선행 사례로서의 ARTEX

ARTEX는 자율 공격 에이전트가 "사람처럼 적응하되 기계처럼 규칙적으로 멈추는" 새로운 위협 범주의 선행 사례다. 이런 에이전트가 보편화될수록, 관제센터는 개별 취약점 대응을 넘어 "자율 에이전트 식별"을 상시 운영 역량으로 내재화해야 한다. 본 문서의 지문 사전·TTP 템플릿·리듬 베이스라인은 ARTEX 한 종에 국한되지 않고, 동류 LLM 공격 에이전트 전반으로 확장 가능한 탐지 자산으로 설계되었다.

10.6 한 문장 요약

취약점이 아니라 에이전트를 탐지하라. 바꾸기 쉬운 시그니처는 공짜 알림으로 깔고, 바꾸기 어려운 LLM의 리듬과 적응 체인에 판정을 걸며, 레이트 리밋으로 구조를 무너뜨려라.
본 문서는 ARTEX LLM 세션 녹화 트레이스와 ARTEX 본체 아키텍처 분석을 근거로, 자율 침투 에이전트의 행위·트래픽 지문을
관제센터가 포착·구별·대응하기 위한 방어용 분석이다. 공격 재현 명령·익스플로잇 코드는 의도적으로 제외하였으며,
대상 DVWA는 보안 교육·검증 전용 환경이다.
