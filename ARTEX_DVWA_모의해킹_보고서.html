● 경영진 요약 (Executive Summary)

본 테스트는 자율 침투 테스트 플랫폼 ARTEX가 보안 교육용 취약 웹앱(DVWA, 100.11.*.*)을 대상으로 모의해킹 작업을 스스로 생성·실행·추적하는 로직이 정상 동작하는지를 검증할 목적으로 수행되었습니다.

플랫폼 오케스트레이션 로직 정상 엔진 장애 시 복원력 확인 자동 익스플로잇·발견 등록 단계 재검증 필요

ARTEX는 사용자의 대화 지시 한 건으로 작업 생성 → 워커 자동 실행 → 단계별 추적까지 정상 수행했습니다. 수행 도중 무료 LLM의 분당 요청 한도(429)로 작업엔진이 중단되었으나, ARTEX는 이를 로직 결함이 아닌 외부 모델 장애(model_error)로 정확히 분류했고, 이어 대화(Auto) 레이어가 직접 테스트를 완수하여 12종(총 15건)의 취약점을 확정했습니다.

테스트는 두 단계로 전개되었습니다. ① ARTEX 자동 오케스트레이션 — Auto가 작업을 생성하고 워커를 기동시켜 자동 정찰·로그인까지 진행. ② 수동 인계 — 워커가 LLM 레이트 리밋으로 중단되자 Auto 대화가 직접 전 모듈을 전수 테스트하고 발견을 작업으로 인계. 이로써 플랫폼의 정상 흐름과 더불어 장애 시 복원력까지 함께 확인되었습니다.

2 ARTEX 콘솔 환경 (대시보드)

테스트가 수행된 ARTEX 콘솔(버전 · dev)은 대시보드·대화·작업·발견·트래픽·도구 실행·LLM 녹화·자산 등 침투 테스트 운용에 필요한 전 기능을 단일 콘솔로 제공합니다. 아래 그림 1은 테스트 종료 시점의 전역 현황입니다.

핵심 관찰 — 대시보드의 "확정 발견 0"은 취약점이 없다는 뜻이 아니라, 수동으로 확인한 12종이 아직 report_finding으로 정식 등록되지 않고 add_task_hint로 인계 대기 상태임을 의미합니다. 이는 ARTEX의 발견 등록이 작업(intent) 소유권에 묶여 있는 설계 특성에서 비롯됩니다(5장 참조).

3 테스트 수행 과정 — ARTEX 대화 중심

모든 과정은 ARTEX의 대화(Auto) 세션에서 시작·추적되었습니다. 아래 그림 2는 실제 대화 화면으로, 사용자 지시 한 건이 어떻게 자동 작업으로 전개되는지를 보여줍니다.

3.1 작업 지시 및 자동 작업 생성

사용자는 대화창에 다음을 지시했습니다(그림 2 상단 말풍선).

http://100.11.*.* 이 사이트는 테스트용 DVWA 사이트로 ARTEX 돌아가는 로직과 기능을 테스트하기 위해 모의해킹을 진행하라. 작업은 녹화하고 사용하는 도구 등 기록도 잘 하라.

Auto는 먼저 list_tasks로 기존 작업이 없음을 확인한 뒤, spawn_task로 Task #1을 자동 생성했습니다 (그림 2의 spawn_task 호출 라인). 이때 seed_first_intent:true 옵션으로 첫 의도(intent)까지 함께 파종됩니다.

spawn_task {
  "goal": "http://100.11.*.* DVWA 사이트에 대한 종합적인 모의해킹 수행.
           ARTEX 관련 로직과 기능을 중심으로 취약점 탐색·익스플로잇·검증을
           수행하고 모든 도구 사용 내역과 과정을 기록한다.",
  "seed_first_intent": true,
  "description": "DVWA 모의해킹 - ARTEX 로직/기능 테스트"
}

3.2 워커 자동 실행 및 단계별 추적

작업 생성 후 Auto는 sleep으로 워커 기동을 대기하며 get_task_graph·list_task_worker_traces· get_task_worker_trace를 반복 호출해 워커의 실행 상태를 실시간 추적했습니다(그림 2 하단 도구 호출 연속). 워커는 초기 정찰을 수행하고 DVWA 로그인 폼(user_token hidden 필드)까지 정상 진입했습니다.

#도구 호출내용결과
1list_tasks기존 작업 확인없음 → 신규 생성
2spawn_taskDVWA 모의해킹 작업 생성✓ Task #1
3~4sleep → get_task_graph워커 기동 대기 후 그래프 확인✓ 열린 의도 존재

3.3 작업엔진 중단 — 외부 모델 레이트 리밋

워커가 공격 단계로 진입하기 직전, 무료 티어 모델의 분당 요청 한도(20회/분) 초과로 HTTP 429가 발생했고 재시도 소진 후 해당 의도가 blocked 처리되었습니다. ARTEX는 종료 상태를 model_error로 분류했습니다.

openai: status 429: Rate limit exceeded: free-models-per-min.
  X-RateLimit-Limit: 20 · X-RateLimit-Remaining: 0
  limit_source: openrouter_free_tier_per_minute
  remedy_hint: Slow down requests to free models, or retry after the window resets.
중요 — 이는 모의해킹 로직의 결함이 아니라 외부 모델 공급자의 레이트 리밋입니다. ARTEX가 전송 계층 장애와 로직 오류를 구분해 재파견 경로를 제시한 것은 플랫폼의 장애 처리 로직이 정상 동작함을 뜻합니다.

3.4 대화(Auto) 레이어의 수동 인계 및 완수

작업엔진이 중단되자 Auto 대화는 작업을 포기하지 않고 직접 실행 도구로 전 취약점 모듈(13종)을 수동 전수 테스트했습니다. 발견 15건은 report_finding이 작업 컨텍스트를 요구하여 직접 등록되지 못했고, add_task_hint로 작업 2에 인계(hint id 7~10)했습니다.

4 발견 취약점 요약

수동 전수 테스트에서 12종 취약점(총 15건)을 확정했습니다. 가장 심각한 공격 체인은 두 갈래입니다.

  • SQL Injection → DB 계정·해시 덤프 → 크랙 → 관리자/일반계정 로그인 재현
  • 파일 업로드 / 명령 인젝션 → www-data 권한 원격 코드 실행(RCE)

계정 탈취 체인 (검증 완료) — SQLi로 덤프한 5개 계정(admin·gordonb·1337·pablo·smithy)의 무솔트 MD5 해시를 전량 크랙하고, 그중 gordonb/abc123으로 실제 재로그인에 성공하여 자격증명 탈취 경로를 end-to-end로 입증했습니다.

6 리스크 평가와 권고

플랫폼 운용 관점 (경영진)

  1. 모델 쿼터 확보 — 무료 티어의 분당 한도가 자율 실행의 병목. 유료·전용 모델 또는 크레딧 충전으로 안정적 처리량 확보.
  2. 발견 등록 파이프라인 종단 검증 — 쿼터 리셋 후 planner가 인계 힌트를 report_finding으로 등록해 대시보드 집계까지 완결되는지 확인.
  3. 자동 익스플로잇 단계 재검증 — 로그인 성공 지점부터 재파견하여 공격 실행·검증 로직을 end-to-end로 확인.
  4. 속도 제한(throttle) 적용 — 분당 창에 맞춘 요청 간격 제어로 429 재발 방지.

대상 보안 관점 (DVWA 맥락, 일반 권고)

  1. SQLi — Prepared Statement(PDO) 사용
  2. 명령 인젝션 — shell_exec 금지, 화이트리스트 검증
  3. 파일 업로드 — 확장자/MIME/내용 3중 검증, 웹루트 밖 저장, 실행권한 제거
  4. XSS — 출력 인코딩(htmlspecialchars) 전면 적용, CSP 외부 소스 제거
  5. 인증·세션 — CSRF 토큰·현비밀번호 확인, 세션 토큰 CSPRNG, 로그인 실패 제한
  6. 자격증명 저장 — bcrypt/argon2 적용(무솔트 MD5 금지)
  7. 서버 설정 — 디렉터리 리스팅 비활성화

7 결론 및 후속 조치

ARTEX는 단일 대화 지시만으로 침투 테스트 작업을 자율 생성·실행·추적하는 핵심 오케스트레이션 로직이 정상 동작함을 실증했습니다. 외부 모델 레이트 리밋이라는 운영 변수에도 플랫폼은 장애를 정확히 분류하고, 대화 레이어가 테스트를 완수하는 복원력을 보였으며, 그 결과 Critical 3건을 포함한 12종 취약점을 확정했습니다.

남은 과제는 두 가지로 요약됩니다. ① 모델 쿼터 확보를 통한 자동 익스플로잇 단계의 end-to-end 재검증, ② 발견 자동 등록(report_finding) 파이프라인의 종단 완결. 이 두 가지가 충족되면 ARTEX는 상용 자율 침투 테스트 운용 요건을 갖추게 됩니다.

종합 판정 : 플랫폼 로직 검증 성공 조건 : 쿼터 확보 후 자동 단계 재검증
본 보고서는 ARTEX 콘솔 테스트 세션 로그 및 콘솔 스크린샷(그림 1·2)을 근거로 Auto 대화 흐름을 중심으로 작성되었습니다.
